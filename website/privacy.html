Privacy policy

Effective 2 November 2026. Project maintainer: dm0.

This policy describes the gdocs-scope-mcp software. You choose the machine running it, the MCP application and any AI provider.

Data access and use

The software accesses Google Docs content, file identifiers and metadata, document structure, comments, suggestions and related author metadata as needed for the tools you invoke. It reads and changes this information to perform document operations requested through your MCP application. Discovery covers application-accessible files or the Google Docs available to your account, depending on the configured mode. Authorization also checks a Google account identifier to keep subsequent consent bound to the same account.

Selected-file mode requests only drive.file for selected and application-created files. Full-drive mode requests only drive for account-wide discovery and document operations. Existing tokens can retain permissions from earlier versions; updating the software or configuring a mode does not revoke previous grants.

Your MCP application and AI provider

Document results, snippets, metadata and edit receipts are returned to your MCP application. It may send them to an AI provider and retain conversations, tool inputs, outputs or logs. These services have their own policies. Installing this software does not establish their retention, training or confidentiality practices. Review them before connecting sensitive documents.

The package itself does not implement model training, advertising or sale of document data. It does not route document contents through a project-operated application backend. A user-chosen remote MCP host still receives those contents.

Credentials and local storage

OAuth refresh credentials are stored in a token file on the machine running the server. New files use owner-only permissions; they are not encrypted by the application. Protect that machine, its backups and remote administrator access. Google authorization exchanges use HTTPS; local MCP communication uses STDIO.

Document caching is disabled by default. If enabled, it can store full native document snapshots in memory or an unencrypted local SQLite file. Expiry prevents reuse after the configured lifetime; it does not guarantee secure erasure. To discard stored snapshots, stop the server and remove its cache files.

Application outcome logs omit tool arguments and results, but error diagnostics and the MCP application can retain additional information. Browser completion URLs contain short-lived authorization codes. When submitted through remote chat or MCP, they may be retained by that host. Do not post those URLs publicly.

Images and network recipients

Opt-in local image uploads send selected images to Google Drive and temporarily make them readable by anyone with the link so Google Docs can insert them. The software attempts to delete temporary source files after insertion and reports cleanup failures. Deleting a temporary source does not remove an image already inserted into a document. Image URL insertion also causes Google to retrieve the supplied image URL.

Google processes authorized API requests under its own policies. The project website uses GitHub Pages for hosting; website request processing and logs are governed by GitHub's privacy statement. The static site includes no analytics, advertising scripts or external fonts. Website hosting does not handle the OAuth code exchange or MCP document operations. See also Google's privacy policy.

Revocation and deletion

Revoke the application's access in your Google Account connections settings. Remove its token files and optional cache from the server machine. Deleting a local token or changing access mode alone does not revoke Google's grants.

These actions do not delete your Google Docs or copies retained by your MCP application or AI provider. Manage those separately with each service. Maintainers cannot directly erase files on machines they do not operate.

Contact

For support and privacy questions: gdocs-scope-mcp@googlegroups.com. Do not include tokens, browser completion URLs or document content. Review the group's archive visibility before sharing identifying information.
