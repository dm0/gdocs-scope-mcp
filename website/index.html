A focused workflow

Outline → section → change

Discover headings, read a selected subtree and apply a change using the text already in the document.

1. Find the “Results” heading.
2. Read Results and its subsections.
3. Replace a matching sentence there.
4. Read the section to verify the change.

Illustrative workflow. The server still fetches the Google Docs snapshot internally to resolve structure and edit positions.

Your choice of access

Connect selected files or use broad Drive access.

Selected files

Use Google Picker to connect documents with drive.file. Add more later; grants persist across server restarts. Pasting a link alone does not grant access.

Full Drive

The compatibility default uses drive for account-wide document discovery and work on accessible Google Docs. It requests broader permissions and has additional Google verification requirements.

More than plain text

Review and edit native document content.

Navigate tabs and heading subtrees. Insert before a heading or after its complete section, including nested subsections and tables, using the heading ID without a text anchor. Read and write rich text, mixed nested lists and rectangular tables. Attach native comments or propose text and formatting changes through native suggestions. Insert image references or explicitly enable temporary Drive uploads for local images.

Colors and highlights

Discover 80 Google editor palette colors or use a custom HEX value. Apply text colors, highlights and paragraph fills using a text anchor scoped to a section or tab. Reset individual color properties while preserving other formatting.

Color examples and reset rules

Rich content and code

Rich insertion starts from document named styles and applies the input's formatting. New table-cell paragraphs use compact spacing. Code blocks support syntax highlighting, configurable themes and line spacing, with a default of 1.15.

Supported content syntax

Check the boundaries before writing.

Rich content supports a defined Markdown and HTML subset; it is not a lossless copy of every Google Docs feature. New tables must be rectangular, and table insertion takes several API batches: a later failure can leave partial content. Code blocks are styled paragraphs. Inspect the document before repeating a write with an uncertain outcome.

Know where your data goes

Run it on the host you choose.

The MCP server runs on your computer or remote host. Google API results are returned to your MCP application, which may send them to an AI provider and retain them under its own policies. Credentials live on the server machine. Read the privacy policy before connecting sensitive documents.
